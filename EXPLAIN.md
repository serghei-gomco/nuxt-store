# Шпаргалка для объяснения (витрина на Nuxt 3)

**Как устроено в одной фразе:** все страницы — готовый HTML, собранный `nuxt generate`; Vue в браузере только
«оживляет» его (фильтр, кнопки, корзина), а корзина живёт в `localStorage`.

1. **Страницы.** Папка `pages/` = маршруты: `index.vue` → `/`, `products/[slug].vue` → `/products/stoneware-mug`,
   `cart.vue` → `/cart`. При `generate` Nuxt открывает `/`, идёт по всем ссылкам и сохраняет HTML каждой страницы
   (16 файлов). Неизвестный slug → `createError(404)` → `error.vue`.
2. **Данные.** `data/products.ts` — 12 вымышленных товаров, цены в центах (чтобы не ловить `0.1 + 0.2`). Чтобы
   подключить API или CMS, меняется только этот файл (или `useFetch` в страницах).
3. **Фильтр через `?category=`.** Ссылки-«чипы» меняют query, `computed` фильтрует список — без перезагрузки.
   Логика в чистых функциях `parseCategory` / `filterProducts` (`utils/filter.ts`), они покрыты тестами.
   - **Тонкость статики:** HTML для `/` один, сервер query не видит. Поэтому до `onMounted` рендерим полный список
     (как в HTML — иначе hydration mismatch), а после — отфильтрованный. Чтобы при прямом заходе на
     `/?category=desk` сетка не «схлопывалась» на глазах, однострочный скрипт в `<head>` до первой отрисовки ставит
     `<html data-category="desk">`, и CSS прячет чужие карточки. Замерено: без него CLS 0.352, с ним 0.
4. **Корзина (Pinia).** `stores/cart.ts`: `add`, `setQty`, `remove`, `clear`, геттеры `count`, `totalCents`, `items`.
   Количество ограничено 10, неизвестные товары игнорируются.
   - **Сохранение:** плагин `cart-storage.client.ts` (только браузер) читает `localStorage` по хуку `app:mounted`,
     то есть **после** гидрации — серверный HTML и первый рендер в браузере совпадают, предупреждений нет. Дальше
     `$subscribe` пишет корзину при каждом изменении. `restore` выкидывает битые и устаревшие записи.
   - **Бейдж в шапке** фиксированного размера: до чтения корзины он пустой, потом в нём цифра — шапка не дёргается.
5. **Скорость** (подробно — `REPORT.md`): всё пререндерено, CSS встроен в HTML, у картинок размеры и
   `aspect-ratio`, high priority только у первых двух картинок, остальные lazy, без веб-шрифтов и внешних запросов,
   без `_payload.json`, префетч страниц по наведению, а не по видимости. Итог локально: 100 / 100 / 100, CLS 0.
6. **Доступность.** Ссылка «Skip to content», видимый фокус, `aria-current` у активного фильтра, подписи у выбора
   количества, «Remove {товар}» у кнопок, `role="status"` для «Added to cart», контраст текста ≥ 5.7:1 (норма WCAG AA — 4.5:1), зоны клика ≥ 44 px.
7. **Тесты (13, Vitest).** Стор корзины без Nuxt (`setActivePinia(createPinia())`): добавление и слияние строк,
   лимит, `setQty(0)` удаляет, итог в центах, восстановление из битого JSON. Плюс фильтр и формат цены.
8. **Деплой.** `vercel.json`: команда `npm run generate`, папка `.output/public` — Vercel отдаёт статику, без функций.

**Частые вопросы клиента:**
- *Почему 100 в Lighthouse, а у нас 40?* Обычно мешают: тяжёлые картинки без размеров, веб-шрифты, сторонние
  скрипты (чаты, аналитика), рендер на клиенте. Здесь это убрано; на реальном магазине начинаю с замера и
  списка «что съедает LCP/CLS», а не с переписывания.
- *Это реальные цифры?* Это лабораторный замер Lighthouse на моём компьютере, команда и дата — в отчёте. Реальные
  пользователи (CrUX) будут после деплоя и трафика.
- *А если товаров 10 000?* Пререндерить все страницы можно, но сборка станет долгой — тогда SSR или ISR
  (`routeRules` в Nuxt) и пагинация/фильтры на API.
- *Где оформление заказа?* Его нет намеренно: это демо витрины и скорости. Checkout подключается отдельно
  (Stripe Checkout или бэкенд магазина).
- *Почему Nuxt 3, если опыт в Nuxt 2?* Коммерческий опыт — Vue 2 / Nuxt 2; этот проект — личный, на Nuxt 3, чтобы
  показать тот же подход (SSR/статика, SEO, скорость) на актуальной версии. Отличия: Composition API, Pinia вместо
  Vuex, `useSeoMeta` вместо `head()`.
